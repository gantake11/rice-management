# フロントエンド選定 & デザイン方針書

本ドキュメントは、お米管理Webアプリ（`rice-management`）におけるフロントエンド技術スタック、UIデザイン方針、およびデジタル庁デザインシステムを活用したシニア対応UIの設計指針を定義したものです。

---

## 1. フロントエンド技術スタック選定

| 項目 | 採用技術 | 選定理由 |
| :--- | :--- | :--- |
| **テンプレートエンジン** | **Thymeleaf 3.x** | Spring Boot標準。HTML構造をそのまま活かしたSSRが可能で、保守性とレンダリング速度に優れる。 |
| **CSSフレームワーク** | **Tailwind CSS 3.x / 4.x** | ユーティリティファーストで余白・文字サイズ・配色の微調整が容易。デジタル庁デザインシステムのデザイントークンをクラスとして直感的に適用可能。 |
| **デザインシステム基準** | **デジタル庁デザインシステム** | 高いアクセシビリティ、視認性、万人にとって迷わないUI設計基準をそのまま流用。AIによるコンポーネント自動生成と相性が極めて良い。 |
| **クライアントJS** | **Vanilla JS (または軽量スクリプト)** | 自宅消費フォームの `[ - ]` `[ + ]` 増減ステッパーや確認モーダルの開閉など、最小限のDOM操作のみに限定し端末負荷を抑える。 |
| **拡張（次期ステップ）** | **PWA (Manifest + Service Worker)** | スマホのホーム画面からアイコン1タップで全画面起動可能にし、ネイティブアプリ感覚の操作感を提供。 |

---

## 2. デジタル庁デザインシステムの導入方針

デザイン作成の手間を減らし、かつ70代の祖母でも迷わず操作できるようにするため、**「デジタル庁デザインシステム（Digital Agency Design System）」** のガイドラインをベースにAI生成でUIコンポーネントを構築します。

### 2.1 カラーパレット（高コントラスト & 誰にでも見やすい配色）
デジタル庁デザインシステムの基本配色に準拠し、WCAG 2.1 AA（コントラスト比 4.5:1 以上）を満たすカラーセットをTailwindで定義します。

* **プライマリカラー（Primary）**: 信頼感と視認性の高いディープブルー (`#0052CC` または `#003882`)
* **アクセント / 成功（Success）**: 補充や完了を表すグリーン (`#00805A`)
* **警告 / 注意（Warning / Attention）**: 在庫不足アラート (`#D9381E` / `#B54708`)
* **背景 / テキスト（Neutral）**: 
  * 背景: 明るいオフホワイト (`#F8F9FA` / `#F0F2F5`)
  * 本文テキスト: 漆黒ではなく目に優しい高コントラストな黒 (`#1A1A1C`)

### 2.2 タイポグラフィ & タップ領域（シニア対応基準）
* **ボタン・タップ領域**:
  * すべての主要操作ボタン（「米をあけた」「米を渡した」等）は **縦幅 `48px` 〜 `56px` 以上** を確保（誤タップを完全防止）。
* **フォントサイズ**:
  * 本文・ラベル: 最小 `16px` (スマホでズームせずそのまま読めるサイズ)。
  * 入力欄・セレクトボックス: `18px` 以上。
  * 重要数値（トップ画面の現在庫数など）: `32px` 〜 `44px` の特大ボールド表示。
* **表現の平易さ**:
  * IT用語・システム用語は使わず、紙のノートに書くような親しみやすい日常語を使用（例: 「トランザクション登録」→「記録する」、「出庫」→「米をあけた/渡した」）。

## 3. AIを活用したコンポーネント生成ワークフロー

デザイン作業を効率化するため、デジタル庁デザインシステムの設計原則をプロンプト化し、Tailwind CSS + ThymeleafのHTMLコンポーネントをAIに生成させます。

### 3.1 AI生成用の共通ルールセット
AIにコンポーネントを作成させる際、常に以下のガイドラインをプロンプトに組み込みます：

```text
【UI生成ガイドライン】
1. デジタル庁デザインシステムの思想（視認性、明瞭な階層構造、十分なコントラスト比）に準拠すること。
2. 70代の高齢者がスマートフォンで片手操作できること（主要ボタン高: 48px以上、文字サイズ: 16px以上、在庫数値: 32px以上）。
3. 余計な装飾（過剰なグラデーションや薄いグレー文字）を排除し、白背景に高コントラストな枠線・文字で構成すること。
4. Thymeleaf属性（th:text, th:if, th:each, th:field 等）を組み込んだクリーンなHTMLを出力すること。
```

## 4. 主要画面のUIコンポーネント構成（Thymeleaf + Tailwind）

### 4.1 トップ画面（ダッシュボード）
* **ヘッダー**: 家族名（「○○さん、こんにちは」）と簡易ステータス
* **巨大在庫カード**:
  * 現在庫数を「残り ○ 袋 (○○ kg)」と特大フォントでカード中央に表示。
* **クイックアクション領域**:
  * 🔴 **「米をあけた（米櫃へ）」**（特大メインボタン・縦幅56px）
  * 🟢 **「米を渡した（親戚へ）」**（特大セカンダリボタン・縦幅56px）
  * 🔵 **「米が入った（収穫・補充）」**（中サイズボタン）
* **直近の履歴カード**:
  * 最新2〜3件の記録をカード形式で一目で確認可能。

### 4.2 数量入力ステッパー (`[ - ]` `1 袋` `[ + ]`)
* 小さな数値入力フォームではなく、指で直感的に押せる `[ - ]` と `[ + ]` の巨大ステッパーボタン（48px四方以上）を配置。

## 5. PWA化に向けた実装準備（Step 2対応事項）

SSRによるWebアプリ動作確認が完了した後に、以下の資産を配置してPWA化を実施します。

1. **Web App Manifest (`manifest.json`)**:
   * `name`: "お米の管理"
   * `short_name`: "お米管理"
   * `display`: "standalone" （ブラウザのアドレスバーを消し、全画面アプリとして起動）
   * `start_url`: "/?key=..." （家族用パラメータ付きURLを起点に設定可能）
   * `icons`: 192x192, 512x512 のアプリアイコン
2. **Service Worker (`sw.js`)**:
   * CSS、アプリアイコン、静的画像などのオフラインキャッシュ配信。
